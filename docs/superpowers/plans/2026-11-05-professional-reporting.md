# 专业 NVIDIA 报告实现计划

> 面向智能体执行者：使用子智能体驱动开发或 executing-plans 逐任务实现。每个任务都需要自审、独立审查，并在 PR 就绪前修复已确认的问题。

**目标：** 让 GitHub SkillEvaluator 的 CLI 和独立 HTML 报告保持一致、易于理解、可访问，并采用 NVIDIA 风格呈现专业外观。

**架构：** 扩展现有的公共状态、呈现、来源、资源和 Harbor 链接抽象。保持规范评估数据和决策策略不变；将共享的呈现投影渲染到 HTML 和终端视图。

**技术栈：** Python、Rich、Jinja2、原生浏览器 JavaScript/CSS、打包的 Chart.js 4.5.1、pytest、Ruff、Fern。

**规格：** 用户批准的 Professional NVIDIA Reporting 计划，以下作为可执行任务复现。仅使用 GitHub 仓库；不导入任何内部源码或集成。

## 全局约束

- 保留评分公式、阈值、发布策略、退出码、CLI 标志/默认值、构建产物文件名、规范 JSON Schema、脱敏和报告大小限制。
- 在隔离工作树中使用 GitHub main 最新版本；保留现有检出及其未跟踪的重复目录。
- 扩展现有共享状态逻辑；不得重复实现判定解析器、不得捏造测量值、不得推断缺失基线、不得修改规范载荷。
- 将 report_scope 现有的决策语义与请求/显示的层级上下文分开。可选的关键字专用呈现参数必须保留现有调用方和 emit_reports() 的布尔返回值。
- 将私有集成和内部插件专用代码排除在公共变更之外。仅使用现有公共记录证据和公共上游资产。
- 每个 PR 包含聚焦的行为测试、文档/变更日志、签署提交、根自审、独立审查，以及已确认问题的修复。
- 发布五个聚焦 PR；验证期间保持草稿，验证通过后标记就绪，保持打开且不合并 main。

## 审查重点

- 已确认的失败加上缺失证据：命令状态必须在终端和 HTML 中一致，同时单独保留更严格的发布评估。
- 缺失/N/A/跳过/仅基线/保留/截断证据：未知不等于零，N/A 不等于执行，预览上限不能改变总数。
- 长恶意或 Unicode 名称/路径：转义标记/HTML/控制字符，保留安全链接，并在窄显示中适配而不丢失数值。
- 离线和已安装 wheel 报告：所有图表资产/许可证均已打包；生成的报告不会为图表发起运行时网络请求。
- 非 TTY 中断/关闭流：持久进度必须干净停止，不影响评估、不重复事件、不泄漏工作进程。

### 任务 1：一致的状态、范围和执行统计

分支：naren/reporting-status-accounting，基于当前 main。

- [ ] 用不可变的最终渲染上下文扩展现有 run_status 和呈现辅助函数：命令结果、单独的发布评估、层级状态/计数、评分范围和每条件覆盖。每次最终渲染构建一次，并在紧凑 CLI、完整 CLI、HTML 头部/主视觉/磁贴之间共享。
- [ ] 保留失败优先级和咨询门控。使用主要标签 Passed required checks / Changes required / Incomplete。将发布资格分开；独立 Tier 3 发布仍为 Not assessed。
- [ ] 明确标注智能体分数（Best agent score）；它们不是整体验证批准。
- [ ] 统计每个层级自身的结果；区分通过、失败、不完整、跳过、未运行和 N/A，将 N/A 排除在执行分母之外。
- [ ] 优先使用记录的每条件已评分/预期计数器，而非预览。显示 N scored trials: X with skill, Y baseline。缺失/格式错误保持不可用，显式跳过保持跳过，旧版行计数是已观察/保留行，不是完整总数。处理重试、提前停止、仅技能/仅基线、部分/失败分支和 >64 预览行。
- [ ] 在 emit_reports 和 HTMLReporter 中必要时添加可选的关键字专用请求/显示呈现上下文，保留默认值、决策 report_scope、返回值和 JSON Schema。不要为缺失磁贴合成 ValidationResult 证据。
- [ ] 先添加有意义的失败测试，实现，运行聚焦的报告/状态/CLI 测试；证明载荷不可变性和状态/计数一致性。更新用户文档和变更日志；签署提交；自审和独立审查。

### 任务 2：真正自包含的 HTML 图表

分支：naren/reporting-offline-charts，独立基于当前 main。

- [ ] 从公共上游引入公共 Chart.js 4.5.1 UMD；使用现有 SRI 验证其原始字节，记录来源/版本/摘要，在资源、声明和生成的报告中保留适用的 Chart.js/捆绑依赖许可证。
- [ ] 使用缓存加载器加载固定包资源，仅在 Tier 3 需要图表时嵌入。移除 CDN/source-map 依赖。不新增 npm/Python 运行时依赖或锁文件变动。
- [ ] 保留图表数据、主题变更、打印重绘和数字格式。添加可访问描述/表格引用和可见的初始化失败回退，而非空白。
- [ ] 在 wheel 和 sdist 中打包资产/许可证。用嵌入式运行时/版本/摘要/许可证测试替换 CDN 测试；确认 Tier 1 避免资产字节，已安装 wheel 渲染无需网络即可工作。
- [ ] 更新文档/变更日志，运行聚焦测试/构建/打包检查；签署提交；自审和独立审查。

### 任务 3：持久 HTML 导航和可访问的 NVIDIA 样式

分支：naren/reporting-workspace-navigation，基于已审查的任务 1。

- [ ] 保留现有 logo、公共深色侧边栏和克制的表面。将主视觉精简为技能、整体决策/原因、标注的智能体结果；将环境/指标/来源详情移入现有披露区域。
- [ ] 全面验证显示所有 3 个层级磁贴，并带有真实的缺失/未请求状态；定向报告保持聚焦范围。侧边栏包含 Summary、Tier 1/2/3 和 Run details；移动端有紧凑的粘性层级导航。
- [ ] 一个激活函数同步侧边栏、磁贴、活动面板、选中状态和焦点。将证据目标放在隐藏层级面板之外；保留精确的发现链接、清除筛选和高亮/焦点。当前侧边栏跟随真实章节导航。
- [ ] 保留 Overview/Insights/Agent Details/Trials/Dataset/Diagnostics。关联标签页/面板和 aria 状态；为子标签和智能体标签提供 roving tabindex 和 Left/Right/Home/End/Enter/Space 支持，包括异常名称。
- [ ] 移除隐藏发现或表格的展开高度上限。单一主页面滚动，仅宽表格水平溢出，仅原始日志/JSON 有界嵌套垂直滚动。原生主题感知滚动条、稳定装订线、强制颜色回退；不使用模拟滚动条。
- [ ] 添加 System/Light/Dark 控件；持久化显式偏好，默认跟随系统。尊重减少动画和打印/无 JS 证据访问及展开恢复。偏移粘性移动/本地导航而不重叠。
- [ ] 使用 lime #76B900 作为强调色，深绿 #3E6500 用于浅色主题文本/操作，炭黑导航，克制的边框/阴影，红/琥珀语义状态。正文 14px，次要标签 >=11px，WCAG AA 文本/控件。
- [ ] 添加行为测试以及 1440/760/390px、两种主题、键盘、长报告、减少动画、无 JS 和打印的浏览器检查。更新文档/变更日志；签署提交；自审和独立审查。

### 任务 4：更清晰的 Tier 2 摘要和完整证据导航

分支：naren/reporting-evidence-views，基于已审查的任务 3。

- [ ] 使用现有类型化工作流和相似性元数据将 Tier 2 拆分为 Within this skill / Across skills。KPI：Checks completed、Duplicate findings、Affected files/skills、Catalog entries compared；明确范围和不可用值。
- [ ] 已完成零匹配不同于跳过/不可用比较。解释目标对目录 vs 成对集合；保留自我排除和重复统计。仅在记录时提供上下文/token 节省。
- [ ] 在 HTML、CLI 和 Markdown 中暴露每个现有规范化 Harbor 作业，包含 Results 和可用的 Analysis。保留名称或 Job N 回退、旧版单作业/仅分析、去重、URL 安全和转义；不推断归属。
- [ ] 在适当的披露区域呈现现有脱敏的扫描器/模型/评估器/数据集/来源信息。保留双分支资源比较、空值、省略计数和完整下载。明确仅技能图表标签；不重复计算缓存 token。
- [ ] 测试缺失/跳过/零匹配工作流、0/1/多个/重复/不安全作业链接、保留报告、可空遥测、限制和不可变性。更新文档/变更日志；签署提交；自审和独立审查。

### 任务 5：一致的响应式 CLI 和持久 CI 进度

分支：naren/reporting-cli-polish，基于已审查的任务 1。

- [ ] 在紧凑/完整/直接 Tier 3 报告中共享轻量语义 Rich 样式。保留绿色/灰色流水线和琥珀编号修复；移除报告视图中不一致的装饰性青色/品红色。
- [ ] 复用等级映射 A/B 绿色、C 琥珀、D/F 红色，并带有失败/不完整/不可用覆盖。显示的零提升为中性；保留不可用/不确定标签和所有评分阈值。
- [ ] 保持每个条件标签/编号/完整条原子化；在窄宽度堆叠并保留所有数字。测试 98/80/60 列和长/宽 Unicode 标签。
- [ ] 在现有完整报告 Details 单元格中添加简洁的成功质量/提升证据；不要展开每个成功面板。
- [ ] 使用生产者实际发出的路径/基名，而非硬编码 report.html。仅对支持交互的输出使用安全超链接；在纯文本/无颜色/重定向/字符串渲染 API 中提供可读路径，不新增 OSC8。保留转义和控制字符剥离。
- [ ] 最终面板输出到 stdout；持久非交互进度输出到 stderr：层级/检查开始、阶段变更、测量的完成里程碑、完成。去重未变更事件；60 秒无进度后心跳。复用进度生命周期，不捏造百分比，干净处理中断/关闭流，不泄漏工作进程。
- [ ] 假时钟进度测试、构建产物/转义/颜色/布局/状态一致性测试、不变的 CLI 表面和 JSON/退出行为。更新文档/变更日志；签署提交；自审和独立审查。

- 每个任务进行聚焦回归测试，然后执行仓库要求的 make lint / make test / make build、Fern 验证、OSS 源码/归档边界、打包和相关兼容性测试。将基线环境失败与回归分开记录；绝不声称未运行的检查已通过。
- 在桌面/移动端和终端宽度、两种主题、无颜色/管道、离线、键盘/减少动画/无 JS/打印下审查相同的合成/保留夹具。报告变更无需实时提供商评估。
- 仅在合理时优化一次分类投影、不可变资产缓存和重复遍历；避免大范围重写和不必要的轮询/工作进程。
- PR 依赖：1 最先；2 独立；3 和 5 跟随 1；4 跟随 3。测试包含所有五个变更的隔离组装集成检出。不要合并 main。
- 交付五个 PR 链接、CI 状态、前后预览和简洁的审查/修复记录。所有提交签署；PR 模板和变更日志/文档已更新。
